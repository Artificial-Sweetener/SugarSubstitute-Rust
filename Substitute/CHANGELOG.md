## [0.2.0](https://github.com/Artificial-Sweetener/SugarSubstitute-Rust/compare/substitute-v0.1.0...substitute-v0.2.0) (2026-11-15)

### ⚠ BREAKING CHANGES

* **updates:** refuse an update engine from the other side of the attempt-channel change
* **installation:** the coordinator-entry launch grammar and the installer worker readiness envelope
advance a version. Installations made by earlier builds migrate on their next launch and keep
their original files in place.
* **session:** restore workspaces, outputs, cameras and window placement on relaunch
* **integration:** camera-change notifications and free-pan restoration require
the paired schema-2 SugarCubes canvas contract. Deploy matching runtime and
SugarCubes protocol contents together.

Validation: exact candidate governance/format/strict compile checks; 52 focused
desktop consumer tests on SugarProofDesk; byte-identical qualified owner suites.
* **canvas:** Native surface discovery and camera notifications require schema 2 within canvas envelope 3. Upgrade SugarCubes and its native host together. Discovery schema 1 receives an empty actionable unsupported response and cannot negotiate operations. Persisted session inspection schema 1 is unchanged.

Validation: cargo xtask check; full contracts 284 + 1 Rustdoc, canvas 167, host 1554; Desktop typed surface 5 and delivery 3. Native-window restoration qualification remains a coordinated integration requirement.
* **canvas:** keep mask content moved beyond the document
* **canvas:** DisplayMapping and ProjectionSamples consume validated
DisplaySample axes. ArchiveStats adds range-read and range-seek counters.
Viewer proof artifacts use schema 5. Existing source archives retain their
format and cache epoch.

Validation: 19 focused regressions, formatting, strict lint/type checks for
affected libraries, and the release viewer build passed. The previously
failing NVIDIA readback case passed headlessly with a 16384-square source
and 3840x2160 output. Full qualification and workspace verification were
not run, following the maintainer's explicit restriction to these fixes.
The separately reported 0xc0000142 startup failure remains unreproduced.
* **canvas:** canvas render requests and view compilation take Reconstruction instead of a filter; pyramids are canonical Lanczos. Native GPU presentation returns a follow-up receipt. Proof metrics use schema 3.
* **canvas:** rename BlockingInputError to OwnedInputError; CPU frames classify Prepared/Projected pixels and acknowledge pending uploads through Lifetime::did_present_cpu. ProjectionBuffer creation receives its retained MemoryLease. Viewer proof metrics advance to schema 2. All workspace consumers are coordinated.

Validation: cargo xtask verify passed on Windows, including governance, formatting, strict Clippy, workspace tests and warning-free Rustdoc. Ten hidden native CPU/Intel/NVIDIA runs passed at 640x480 and 3840x2160 with final pixels matching complete DAG reconstruction. The large source is 16384x16384. macOS/Linux and manual interaction remain unqualified.
* **canvas:** desktop canvas lifetimes implement feedback() and receive tool,
temporary-navigation and display-refresh observations. Replace legacy viewport
inputs with ToolInput in physical pixels. Navigation::next_deadline returns
Option directly. All workspace consumers and proof adapters are updated.
* **canvas:** image operation Rectangle requires an explicit output translation and axis_coverage accepts signed grid coordinates. Existing unshifted nodes use [0; 2]. All workspace consumers are updated; persisted source archives and host protocols are unchanged.
* **storage:** synchronous splash rendering returns Raster and character painting accepts Raster; callers no longer receive or provide tiny-skia Pixmap values.

Windows validation: cargo xtask verify (4725 Rust test executions, zero failures or ignored tests); governance, formatting, both strict Clippy configurations and warning-free Rustdoc passed for these exact contents.
* **localization:** installer workers require textProtocol 1 and closed product
message codes. InstallerLifetime implementations provide the selected Messages
catalog; InstallerMessages exposes named fields instead of positional key lookup.
All consumers in this checkout are migrated together. Persisted locale selection
and the supported locale registry are preserved.
* **cache:** provisioning cache readiness requires protocol 2. Package the
host and worker together; legacy protocol-1 peers are rejected before
provisioning. Persisted cache markers and generation records retain schema 1; cached
payload bytes remain compatible.
* **desktop:** reload frontend while retaining ComfyUI backend
* **lifecycle:** native lifecycle peers require protocol 6. Parent and desktop
are shipped together; restart the matched host to establish new sessions.
* **host:** lifecycle wire 5 and diagnostic command schema 2 reject previous peers. Rebuild and deploy all roles together. Reporter content requires owned static state for uncertain native retention; persisted authored data is preserved.
* **startup:** preserve failed attempts and native readiness
* **ipc:** carry attempt-bound startup and output messages
* **qualification:** record bounded native startup phases
* **presentation:** prepare admitted frames outside native callbacks
